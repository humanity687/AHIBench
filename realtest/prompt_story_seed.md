# 任务：生成"长程记忆检索基准"种子故事 + 事实表

请生成一份中文短篇小说种子文本及其配套事实表，用于测试"长程记忆上下文管理数据结构"在真实 LLM 场景下的表现（检索召回 / 编辑失效 / 状态一致性）。

## 一、故事要求

1. 篇幅 **3500~4500 字**（中文）。纯叙事散文，段落间用空行分隔。**不要**章节标题、注释、元叙述。
2. 故事要足够"密"，必须包含：
   - **至少 5 个有名字的人物**：名字 2~3 字、彼此不同、无谐音混淆；
   - **至少 6 个具体地点**：每个有独特名称或可区分的明确描述；
   - **至少 6 个具体物品**：有名称/特征/归属，且多数物品在**后面会再次出现或被明确提及**；
   - **明确的时间线**：至少跨越 5 天，使用"第X天""清晨/正午/黄昏/深夜""三更"等明确时刻标记；
   - **至少 3 条明确的人物关系**（亲属/师徒/主仆/债务/隐瞒等），在文中直接写清；
   - **至少 3 处长程伏笔**：开头 1~2 段埋下的一句话细节，在结尾 1~2 段必须回收或明确呼应。
3. 事实要"硬"：
   - 人名、地名、物品名、时间、数字、动作**精确且不重复**（不要出现"那把刀""那口井"这类无标识的指代）；
   - 人物物理行为一致：出现在哪里就是哪里，时间不能倒流；
   - 不要隐喻性、不可验证的表述。
4. 风格不限（志怪/市井/武侠/日常均可），但必须是**完整闭环的短篇**：有起因、发展、转折、结尾。

## 二、事实表要求

1. **30~40 条事实**，覆盖四类：
   - 人物身份与关系：8~10 条
   - 物品归属与位置：8~10 条
   - 时间地点与事件：8~10 条
   - 状态与立场：4~6 条
2. 每条事实格式（Markdown 表格，列：`id | 问题 | 必含片段 | 类别`）：
   - `id`：F01、F02……连续编号；
   - `问题`：一句可直接回答的话（例："阿福第一次出场时在做什么？"）；
   - `必含片段`：1~3 个**从故事原文逐字摘取**的字符串片段（每个 4~10 个字），用中文分号分隔；正确答案必须包含这些片段；不同条目之间的片段**不得互相重复**；
   - `类别`：人物 / 物品 / 时空 / 状态。
3. 问题的答案必须**仅凭故事原文即可确定**；必含片段必须**逐字出现**在故事原文中。
4. 事实在全文分布均匀：开头 1/3、中间 1/3、结尾 1/3 各占约三分之一。

## 三、输出格式

```
第一部分：故事正文
（空行分隔的段落，无任何标记）

第二部分：事实表（Markdown 表格）

第三部分：人物名单（每行一个人名，只输出名字本身）
```
