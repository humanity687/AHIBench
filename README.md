# 水循环 v2 · 参考资料上下文管理运行时

> 把一份长参考资料变成"位置有序、分辨率可变、可编辑演化"的记忆树，
> 让 Agent 在有限上下文窗口里稳定地工作于任意规模的参考资料之上。

**当前状态：理论设计阶段，尚未编写功能代码。** 路线：先按设计文档实现 → 属性测试 → 三组对照基准 → 参数校准。

---

## 要解决的问题

一份长参考资料（一本书的全文、一份大型文档集）无法整体塞进有限的上下文窗口。已有的三种做法各有致命伤：

| 做法 | 问题 |
|---|---|
| 全量发送 | 窗口爆炸，且"塞得下"≠"记得住"（注意力衰减） |
| 静态摘要拼接 | 丢细节，无法承载状态的演化 |
| 关键词检索 | 无状态、无结构，检索到的片段孤立无上下文 |

**核心矛盾**：参考资料是"长期演化的内容"，而现有方案都在用"无状态的文本生成"去逼近它。

## 核心思想（四条）

1. **位置有序的记忆树**——参考资料切成原子卡（句粒度），按原文顺序组织；摘要卡按连续区间自底向上合并成树。树的任何节点 = 某一段连续区间的概括。
2. **分辨率随热度变化**——近处（当前工作区）全分辨率原文，远处自动降为各级摘要；越老的记忆越粗、但越稳定。像人读书：近处清晰，远处模糊。
3. **编辑即失效，重建即蒸馏**——任何修改精确地使受影响区间失效，被改内容立即从所有查询中排除；重建全部推迟到蒸馏时机，编辑路径本身零 LLM、零阻塞。
4. **不可遗忘的事实层**——与正文流分离的"笔记本"：无衰减、全量存储、按需注入。负责跨区引用（伏笔/回调）与硬约束，不做概率性召回。

## 架构一览

```
┌─ 三轨记忆（单一 SQLite 持久化）──────────────────────┐
│ 轨道A 参考资料流   记忆树 + 原子层 + 历史归档        │
│ 轨道B 笔记本       常驻约束 / 状态条目 / 调度条目    │
│ 轨道C 工作记录     工具组压缩卡，自然遗忘            │
├─ 调度原则───────────────────────────────────────────┤
│ 组装：每次工具调用一次，纯计算（零 LLM）            │
│ 蒸馏：章节边界 / 预算超标 / 低 HP 承压条件式触发    │
└─────────────────────────────────────────────────────┘
```

关键机制：

- **近热远粗的上下文**：每个工具调用时，上下文 = 全局概述层 + 与当前任务相关的召回路径 + 最近工作区的全文原文，预算恒定。
- **区间失效**：任何编辑（AI 工具或用户界面，同一条路径）通过位置区间精确失效旧内容，改动区域立即从"摘要层"剥落为"原文层"，衰减后自动重新融合。
- **检索不挑深度**：对整棵记忆树打分，命中节点连同其祖先路径一并注入——深度随遗忘历史自然变化，无需人工指定层级；精确引用走独立的逐字校验通道，杜绝"回忆变编造"。
- **事实不遗忘**：伏笔、设定、角色状态存放于独立笔记本，按当前任务目标精确选取注入，全量存储、绝不衰减。

## 首个应用：长篇小说写作 Agent

- 分阶段写作（write / rewrite / edit / recall / ask），每章一个固定流程：目标进入 → 预检索 → 写作循环 → 章末蒸馏 + 事实对账 + 版本快照。
- 伏笔（调度条目）按埋设/推进/回收窗口强制注入；章节完成时自动"对账"：新章事实声明与笔记本比对，冲突由作者裁决。
- 每章恒定 ~14k 字符上下文预算，与全书规模无关。
- 通用化：章 → 结构单元，beat → 内容块，伏笔 → 跨区引用账本。本机制同样适用于代码库、研究文档、项目资料等任何"参考资料"场景。

## 实验计划（先于功能验收）

1. **属性测试**：编辑标记完备性、铺陈不变量、边界条件穷举、回滚对称性。
2. **延迟回忆基准**：固定大纲写 20 章 → 续写第 21 章 → 检测对第 1 章伏笔/角色的引用正确率，与"全量发送 / 摘要拼接"对照。
3. **状态一致性基准**：注入事实变更（改名/死亡/恢复）→ 检测后续章节一致性。
4. **token 计量** 与 **人类找茬**。
